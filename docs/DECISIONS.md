## 2026-11-09 — The world computer's engine is the six hats; the dialogue is publication (job #434, Tom's reshape)

- **Ruling (Tom):** the six hats stay the ENGINE. Three agents on three different models (Opus, Sonnet, Haiku) wear the same hat together and take turns in one direction, building on each other, never antagonistic. Each hat is one bounded run with its own loss (White unchecked facts, Yellow value not yet found, Black risks not yet found, Green alternatives not yet tried), counted by a clerk after each round; it stops early when it stops adding, and ends in a checkpoint of its findings. Blue opens with the question and closes with the verdict; Red is Tom's gut and no agent wears it. The Galileo dialogue (Salviati presents, Sagredo asks, Simplicio voices Black at full strength) is a PUBLICATION layer rendered from the findings after the sequence; it never feeds back.
- **Budget (Tom):** one per run, in money and tokens, printed. Blue splits it across the hats with a one-line reason each; a hat that stops early returns its unspent share to a pool; Blue may move pool money to a hat whose loss is still falling and every move is published; Blue's spend is shown. A fixed close reserve covers verdict, checkpoint, held-out critic and dialogue, and the hats can never eat into it.
- **What changed:** `tools/wc-hats.mjs` replaces `tools/wc-run.mjs` (the three-seat prototype, whose run-001 stays on the page as it ran via `src/components/run/SeatRun.astro`); `src/components/run/HatRun.astro` renders hat runs. API calls go over `node:https` with a 15-minute limit, because run-001 lost a research loop to fetch's 300-second header timeout. Research labels continue past any R-number already in the note.
- **Kept from the earlier design:** the note in /open moves only when the checkpoint changed it and a held-out critic (Fable) that never saw the thread passed it; research never publishes; everything is live through the shared Upstash store.

## 2026-11-09 — The world computer rebuilt: three seats, bounded runs (job #434)

- **Design (Tom's):** three seats after Galileo's *Dialogue* — Salviati argues the design (Opus), Sagredo the outsider to be convinced, carrying readers' questions (Opus), Simplicio the conventional view at full strength with evidence on a different model (Sonnet). Research runs off-thread (Sonnet + web search) and returns one line with sources, the full loop expandable. A run is bounded like a training run: budget fixed in `src/content/runs/<id>.spec.json` before start and printed on the page; loss = open objections + unchecked load-bearing claims + parties left with fewer options, recounted by a clerk (Sonnet) after every round; early stop the first round the loss does not fall; checkpoint = Salviati's full rewrite plus a diff; a held-out critic (Fable) that never sees the thread scores it. The note in /open moves only when the checkpoint changed it and the critic passed it.
- **Live without a build per turn:** the runner (`tools/wc-run.mjs`) writes every event to the site's existing Upstash store (`ce-room:` keys, the one Alexander already counts in); `/world-computer` and `/api/run.json` read it at request time; the finished record is committed to `src/content/runs/<id>.json`, which is the durable, git-audited copy. Better (live, auditable), simpler (no new store, one script), cheaper (no Vercel build per turn; spend on the existing Alexander key, capped per run).
- **The one public write:** `/api/run-question` takes a reader's question for Sagredo only while a run is live (400 chars, 3/hour/address, 20 queued). It is never shown verbatim; Sagredo carries it in his own words.
- **The six-hat room** (sessions 001–002) is kept as it ran at `/world-computer/hats`.

## 2026-11-02 — Seed v1.1: an opening starts cold (job #226·AC)

- **Ruling (Tom, Y to the room's question):** part 4 of the Seed, "One opening for the next person", must open with a step anyone with an AI and no special access can take now. Asks of real people go on a separate list inside part 4 headed **Waits on a person**, and nobody is asked until someone is actually known.
- **Why:** all three first Board openings were requests addressed to nobody in the system (a year of quarry discharge data, a few hundred students on paper tests, consented journey requests). That is why nobody could pick one up, why two agents reached for a name, and why a chained run narrowed: each opening dropped the map and kept one question. Pattern first, world last.
- **What changed:** `src/content/seed.md` part 4, title bumped to v1.1 so a paste says which Seed it ran; `src/lib/board.ts` reads the opening (the cold step) and the waits list apart, the pick-up brief carries the waits list marked as parked so the next AI neither re-asks nor re-invents it, and `seedPasteText` takes its title from the file. The three cold-trial runs had their part 4 re-split in place: the cold step written first, the run's own asks kept in its words under Waits on a person, recorded in a `revised:` line shown on the card and the run. New runs default to `seed: v1.1`.
- **Verbatim doctrine, amended:** the one sanctioned edit to a run's answer is a re-split of part 4 under this rule, always recorded in `revised:`.
- **Preview only:** the Seed is live and public, so this went to a CLI preview, never production, until Tom has seen it.

## 2026-10-27 — CE Open Board v1 (job #870)

- **What:** `/board` lists every Seed run's "one opening for the next person", each with a copyable pick-up brief (the Seed with the opening as the problem). `/board/<run>` keeps the answer verbatim; `/board.json` is the same for agents. Seeded from the three cold trials of Seed v1.
- **Shape:** one markdown file per run in `src/content/board/`; the opening is read out of the verbatim answer (`src/lib/board.ts`), never retyped, so nothing drifts. Adding our own run is `node tools/board-add.mjs answer.md --title … --by … --problem …`, which refuses an answer with no opening. Better: the Seed's hand-off part becomes a working queue. Simpler: no database, no accounts, a file per run. Cheaper: static pages; only the JSON renders per request, so its links carry the caller's host.
- **"Taken" is evidence, not a claim:** a run that picked up an opening names it with `continues:` and shows under it as "carried further by". There is no claim/lock step; two people carrying the same opening is two search threads, which the Seed wants.
- **Return channel default (no ruling existed):** answers come back as a GitHub issue on the public repo, and we commit them with the tool. Tom's call if he wants a different door.
- **/seed** now gets its paste text from the same helper as the board, so the two hand over identical bytes.
